# DAG STUDIO CMS

**Универсальная CMS для сайтов администраций, компаний, организаций и магазинов.**

> Статус: ранняя версия (MVP). До промышленного запуска необходимы тестирование на хостинге, аудит безопасности и подготовка юридических документов.

## Оформление DAG STUDIO CMS

Система оформления основана на фирменном дагестанском орнаменте:

- **Тёмная тема** — медный знак `assets/ornament-dark.svg` на графитовом фоне.
- **Светлая тема** — медно-чёрный знак `assets/ornament-light.svg` на тёплом светлом фоне.
- Оба SVG используются как **адаптивные фавиконы**; переключение выполняется через `assets/theme.js`.
- Тема сохраняется в браузере и применяется на установке, входе, административных и публичных страницах.
- Оформление мастера установки ориентировано на Full HD 1920×1080, на меньших экранах адаптивно перестраивается в одну колонку.
- Панорамный горный фон используется только в фирменном оформлении установщика: `assets/mountain-scene.svg`.
- Фирменные элементы не изменяют права, работу с MySQL, регистрацию и проверку паролей.

## Релиз конструктора шаблонов

Версия с четырьмя редактируемыми шаблонами, индивидуальными настройками и интеграционными тестами подготовлена к развёртыванию через FTPS.

## Каталог шаблонов и конструктор

В админке появился отдельный пункт **«Шаблоны и дизайн»**. В нём можно выбрать один из четырёх готовых типов:

- **Организация:** миссия, направления и новости.
- **Компания:** услуги, преимущества и презентационный экран.
- **Магазин:** товары с ценами, каталог и предложения.
- **Администрация:** официальный стиль, новости, документы (страницы), услуги и обращения.

При смене шаблона сохранённые материалы и пользователи **не удаляются**. Индивидуальные настройки оформления, текстов и порядка блоков сохраняются для каждого шаблона отдельно. Набор необходимых модулей включается без отключения ранее активных модулей.

Для каждого варианта доступны: акцентный цвет, фон, цвет текста, шрифт, ширина, скругления, стиль карточек, верхнего меню и первого экрана; заголовки и тексты, две кнопки и их URL, логотип PNG/JPEG/WebP до 2 МБ, изображение первого экрана до 5 МБ, три редактируемые карточки, четыре дополнительные ссылки меню, телефон, адрес, текст подвала, видимость и порядок шести типов блоков.

Кнопка **«Предпросмотр»** доступна только администратору и показывает альтернативный шаблон, **не изменяя** активный. Для организации, магазина и администрации по умолчанию используется светлый стиль, для компании — тёмный; посетитель может переключить тему.

Новые настройки хранятся в существующей таблице `settings` без миграции схемы. Пользовательские изображения находятся в `assets/uploads`; эта папка должна быть доступна PHP для записи, загруженные изображения исключены из синхронизации FTPS, а выполнение серверных скриптов в ней запрещено.

**Границы текущей версии:** магазин пока представляет собой витрину товаров с ценами и контактами — корзина, оплата и доставка не реализованы. Для администрации документы выводятся как обычные страницы; специализированные реестры, документооборот и юридические механизмы публикации будут отдельными модулями. Конструктор редактирует основные визуальные блоки, но пока не является свободным drag-and-drop редактором.

## Возможности первой версии

- Мастер установки с подключением MySQL/MariaDB.
- Авторизация в административной панели, пароль в виде стойкого хеша и ограничение попыток входа.
- Страницы, новости, услуги и товары: создание, правка, публикация и удаление.
- Разделы «Обращения», «Пользователи», «Настройки».
- Роли «администратор» и «редактор», отдельные права редактора по разделам.
- Адаптивный тёмный дизайн DAG STUDIO CMS на русском.
- Контактная форма с защитой CSRF, ограничением частоты отправки и обязательным согласием. Она отключена, пока не указан URL опубликованной политики персональных данных.
- GitHub Actions: проверка синтаксиса PHP; развёртывание на хостинг по защищённому FTPS.

## Требования к хостингу

PHP 8.4 или новее (расширения pdo_mysql, mbstring), MySQL 8 или совместимая MariaDB, Apache 2.4 или LiteSpeed с .htaccess, HTTPS.

В текущей версии **одна установка CMS обслуживает один сайт**. Полноценная мультисайтовость, корзина и заказы магазина, медиа-библиотека, свободный drag-and-drop редактор и система плагинов — следующие этапы.

## Установка

1. На хостинге создайте пустую базу MySQL и пользователя с правами создания таблиц.
2. Передайте файлы CMS в корень сайта вместе со служебными папками app, database и storage.
3. Дайте PHP права записи в каталог storage, но не открывайте к нему HTTP-доступ.
4. Откройте https://cms.dagstudio.ru/install.php, введите параметры базы, тип сайта и данные администратора (пароль не менее 12 символов).
5. Перейдите на /admin/login.php. После установки повторный запуск мастера блокируется.
6. До сбора обращений создайте настоящую политику обработки персональных данных и пропишите URL в административных настройках.

Секретные настройки база данных хранит на сервере в storage/config.php. Этот файл исключён из Git.

## Настройка FTPS из GitHub

GitHub → Settings → Secrets and variables → Actions:

| Вид | Имя | Значение |
|---|---|---|
| Secret | FTP_SERVER | FTPS-адрес хостинга |
| Secret | FTP_USERNAME | Имя FTP-пользователя |
| Secret | FTP_PASSWORD | Пароль FTP |
| Variable | FTP_SERVER_DIR | Путь сайта на сервере, например /public_html/ — уточните у хостинга |
| Variable | FTP_ENABLED | true для автоматического развёртывания после коммитов |

Пока FTP_ENABLED не установлена в true, каждый push в main запускает только проверку PHP. Ручной деплой доступен через вкладку Actions и Run workflow после добавления секретов.

**Важно:** протокол FTPS (FTP с TLS), порт 21. Если сервер поддерживает только SFTP, требуется другой способ передачи. Перед первым деплоем проверьте папку назначения и сделайте резервную копию.


## Проверка первого подключения FTPS

1. Проверьте, что `FTP_ENABLED` создана как **Repository variable** со значением `true`, а `FTP_SERVER_DIR` указывает именно на корень `cms.dagstudio.ru` (не на соседний сайт).
2. Укажите `FTP_SERVER`, `FTP_USERNAME`, `FTP_PASSWORD` в **Repository secrets**, не публикуйте значения в логах, коммитах или сообщениях.
3. Откройте **Actions → Проверка и публикация DAG STUDIO CMS**. Сначала должен завершиться шаг «Проверка PHP», затем «Загрузка сайта по FTPS». Если второй шаг `skipped`, переменная включения не прочитана или отсутствует.
4. Успешная задача FTPS подтверждает передачу файлов, но не работу сайта. Проверьте HTTPS, страницу установки, PHP, подключение к базе, авторизацию и защищённость папки `storage`.
5. Не выполняйте повторный деплой при неуверенности в `FTP_SERVER_DIR`. Создайте резервную копию перед первым развёртыванием.

## Восстановление доступа администратора

При входе используйте e-mail и **пароль администратора сайта**, которые вводились в разделе «Администратор» мастера установки. Это не пароль MySQL/FTP.

Если вход не удаётся, проверьте существующих пользователей через phpMyAdmin (база текущей CMS):

```sql
SELECT id, email, role, active FROM users ORDER BY id;
```

Если нужная запись есть, `role = admin` и `active = 1`, восстановите пароль без удаления базы через SSH-консоль хостинга. В корне `/www/cms.dagstudio.ru` выполните (замените адрес почты реальным e-mail администратора из запроса):

```bash
cd /www/cms.dagstudio.ru
read -r -s -p "Новый пароль администратора: " CMS_NEW_PASSWORD; echo
printf '%s\n' "$CMS_NEW_PASSWORD" | php tools/reset-admin.php "admin@example.ru"
unset CMS_NEW_PASSWORD
```

Пароль длиной 12–72 байта **не выводится в командной строке, не сохраняется в репозитории** и передаётся инструменту через STDIN. Скрипт доступен только в PHP CLI; прямые HTTP-запросы блокируются. Он обновляет пароль **существующего активного администратора**, не создаёт новые учётные записи и не меняет содержимое сайта. После семи неверных попыток для одного e-mail/IP вход может быть временно заблокирован на 15 минут. Если `users` пуста или в ней нет активного администратора, сначала необходимо разобраться с состоянием установки — не удаляйте базу без резервной копии.

## Структура

- app/core.php — ядро, PDO, CSRF, сессии, разрешения.
- install.php — установка CMS.
- database/schema.sql — схема БД.
- admin/login.php — вход и выход.
- admin/index.php — административная панель.
- admin/actions.php — обработчики управления.
- index.php — публичный сайт.
- assets/style.css — оформление.
- .github/workflows/deploy.yml — проверка и публикация.

**Порядок разработки:** GitHub → тесты → FTPS → проверка живого сайта.
